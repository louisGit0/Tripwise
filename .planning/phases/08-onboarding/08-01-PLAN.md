<objective>
Add a post-signup onboarding tour to the web app: a full-screen, editorial-dark multi-step
carousel that auto-shows once per user on first authenticated load, is dismissible, and can be
replayed any time from Settings.

Purpose: New users land in a working app with no explanation. ONB-01 gives them a guided
walkthrough of the app + each screen, replayable on demand — with zero backend (a client-side
per-user "seen" flag in localStorage).

Output: A seen-flag util, a self-contained `OnboardingTour` component, the auto-trigger mounted
in `AppLayout`, and a "Revoir le tutoriel" entry in web Settings.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser localStorage | client-only per-user "seen" boolean keyed by user id |
| client → /auth/me | reads the already-authenticated user id (no new endpoint, JWT auto-injected) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01-01 | Information Disclosure | localStorage seen flag keyed by userId | accept | The value is a non-sensitive boolean and the user id is already present in the user's own JWT/cookie; no secret, no PII beyond the user's own id on their own device. |
| T-08-01-02 | Tampering | user clears/sets the flag locally | accept | Worst case the tour shows again or never — purely cosmetic, no security or data impact. |
| T-08-01-03 | Spoofing/Elevation | replay window event | accept | The event only opens a read-only UI overlay; it triggers no privileged action and carries no data. |
| T-08-01-SC | Tampering | npm installs | mitigate | No new dependency is added (a few divs/state + existing atoms/hooks); if any install is proposed, stop — none is required. |
</threat_model>
