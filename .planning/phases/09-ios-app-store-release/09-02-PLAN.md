<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/users/me | authenticated DELETE (cookie-derived JWT injected by `apiClient` interceptor) |
| browser → /privacy | unauthenticated GET on a public Next.js static page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02-01 | Tampering | confirm Modal bypass | mitigate | DELETE only fires from `handleDelete` invoked by the Modal's danger button — same React state machine as the existing logout Modal; no `fetch` from an unprotected handler. |
| T-09-02-02 | Information Disclosure | privacy page content | accept | Page is intentionally public and contains no user data — only policy prose + a public contact email. |
| T-09-02-03 | Repudiation | user-initiated deletion | accept | Server-side action is logged at the Render request layer; no app-level audit log in v1.0 (T-09-01-03 parity). |
| T-09-02-04 | Spoofing | post-delete navigation | mitigate | `logout()` clears the BFF cookie BEFORE `router.replace('/')` — a leftover cookie cannot re-authenticate a deleted account because the JWT no longer matches an existing user row. |
| T-09-02-SC | Tampering | npm/pip/cargo installs | mitigate | No installs in this plan — N/A. |

</threat_model>
