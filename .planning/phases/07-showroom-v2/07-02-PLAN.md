<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → our API | authenticated calls to GET /vehicles/catalog (search) and GET /vehicles/catalog/image (photo) |
| our API → browser | returns a photo URL string (CarImages CDN) the browser renders in an `<img>` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Information disclosure | CARIMAGES_API_KEY | mitigate | The browser never sees the key — it calls OUR endpoint (07-01) which returns only `{ imageUrl }`. No CarImages key in the web bundle. |
| T-07-02-02 | Tampering (XSS) | rendering the returned imageUrl | mitigate | The URL is rendered ONLY as an `<img src>` (image context — no script execution, no innerHTML/dangerouslySetInnerHTML); `onError`→placeholder handles a bad/dead URL; 07-01 validates `https://`. |
| T-07-02-03 | Denial of service (quota) | per-card image fetches | mitigate | 07-01 caches hits+misses (30-day TTL); the showroom paginates (~60/page) and images lazy-load — repeated/identical lookups are cache-served. |
| T-07-02-SC | Tampering | npm installs | mitigate | No new dependency (native `<img>` + existing axios/atoms); package-legitimacy gate N/A. |
</threat_model>
