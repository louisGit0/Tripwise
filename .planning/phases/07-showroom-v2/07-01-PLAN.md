<objective>
Phase user story (derived from the ROADMAP Phase 7 Goal — user-observable):
**As a** driver adding a vehicle, **I want to** see real vehicle photos in the showroom (with a clean fallback when none exist), **so that** I can recognise and pick my car at a glance.

This plan delivers the backend foundation of SHOW-02: a server-side image-resolve service + a JWT-guarded endpoint that returns a photo URL by canonical brand+model, reading `CARIMAGES_API_KEY` server-side only, cached and never-throwing, degrading to `{ imageUrl: null }` so the whole feature SHIPS WITHOUT THE KEY (the client renders a brand placeholder everywhere; photos "light up" once the key is set in prod). Mirrors the existing `TollService` (TollGuru) integration shape exactly.

Purpose: Give web (07-02) and mobile (07-03) a single, key-safe endpoint to call for each model's photo, with graceful degradation identical to tolls.
Output: `VehicleImageService` + `GET /vehicles/catalog/image` + `.env.example` entry + unit spec (mocked fetch) + e2e (no-key → null).
</objective>

  <behavior>
    - resolveImageUrl(make, model): with a key + mocked ok response containing an image URL → returns that URL (string).
    - No key configured → returns null WITHOUT calling fetch.
    - Non-ok HTTP (401 unauthorized, 429 over-quota, 5xx) → returns null, never throws.
    - Timeout / network rejection (AbortSignal.timeout) → returns null, never throws.
    - JSON/parse failure or unrecognised response shape → returns null, never throws.
    - The request carries the key in the auth header (assert header value === the configured key); the key is NEVER part of the returned value.
    - A second identical resolveImageUrl(make, model) is served from cache → fetch called exactly once.
    - Empty/blank make or model → returns null without fetching.
  </behavior>
  <action>
    Create `VehicleImageService` (@Injectable, constructor `private readonly config: ConfigService`, a `private readonly logger = new Logger(VehicleImageService.name)`). Read the key once per call via `this.config.get<string>('CARIMAGES_API_KEY')`. Add an in-memory `private readonly cache = new Map<string, { url: string | null; expiresAt: number }>()` with a long TTL constant `CACHE_TTL_MS` (use 30 days, like the toll cache — image URLs are stable) so repeated/identical model lookups stay well under the 5k/month free tier; cache BOTH hits and misses (null) so a missing model does not re-hit the API every render. Cache key = normalized `` `${make}|${model}`.trim().toLowerCase() ``.

    Public method `async resolveImageUrl(make: string, model: string): Promise<string | null>`:
    1. Trim make/model; if either is empty → return null (no fetch).
    2. Compute the cache key; on a non-expired cache entry return its `url` immediately (no network).
    3. If no key → cache+return null (no fetch).
    4. Build the outbound request defensively against the CarImages free API (carimagesapi.com): declare a module-level `CARIMAGES_BASE_URL` constant and an `IMAGE_TIMEOUT_MS` (8000, like toll). Build the query string from `make`/`model` (and you MAY pass a default angle) using `encodeURIComponent` on each value — NEVER interpolate raw input into the URL. Send the key in the request header (the CarImages convention — confirm header name vs query param against the live docs at integration; if the docs specify a query-param key instead, send it there). Use `fetch(url, { signal: AbortSignal.timeout(IMAGE_TIMEOUT_MS) })`.
    5. On `response.ok`: parse defensively — CarImages may return JSON containing a URL (e.g. an image-URL field or a results array) OR a direct image. Extract the FIRST plausible absolute `http(s)` image URL via a small defensive reader (try a couple of known fields, else null); validate it begins with `https://` (drop anything else). Cache+return the URL or null.
    6. On non-ok status → `logger.warn` once + cache+return null. On any thrown error (timeout/network/parse) → catch, `logger.warn`, cache+return null. NEVER rethrow.

    Add the matching unit spec mirroring toll.service.spec.ts: a `makeService(apiKey?)` helper with a ConfigService stub returning CARIMAGES_API_KEY only, `jest.spyOn(globalThis, 'fetch')`, okResponse/errResponse helpers, and one test per behavior bullet above — including an explicit assertion that the configured key appears in the outbound request (header) AND that the returned value is just the URL string (no key substring), plus the cache-once assertion.

    Do NOT add any npm dependency (native fetch + existing Nest deps only). No console.log.
  </action>
